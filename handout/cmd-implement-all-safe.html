/implement-all-safe

← Back to index

Summary

Portable runtime-agnostic loop that repeatedly runs /implement-next against a plan file, executing every step inline in the current context — no subagents are spawned. It works in any harness (Claude Code, Cursor, claude -p) without hook dependencies, and is also the mode /implement-all switches to automatically when its Agent tool is unavailable (Cursor, claude -p, Claude Code < 2.1.172).

When to use

Use /implement-all-safe directly when your harness has no subagent primitive to spawn tasks with, or when /implement-all has already selected it for you after its version check.

  • You are running in Cursor, claude -p, or another harness without an Agent/Task tool.
  • Your Claude Code build is older than 2.1.172, so the Agent tool cannot be used for per-task subagents.
  • /implement-all invoked this command automatically after its Step -1 version check found CLAUDE_CODE_EXECPATH unset or the version too old.

Critical constraints (enforced by the command itself):

  • Does NOT spawn subagents — every step of every task executes inline in the current context.
  • Implements EXACTLY ONE task per loop iteration — no previewing or preparing subsequent tasks.
  • Retries the same task (not later tasks) if its checkbox does not flip, up to 3 attempts, then stops and reports "Manual intervention required."

Invocation

Pass the path to the plan file as the sole argument.

/implement-all-safe [plan-file-path]

Parameters:

  • [plan-file-path] — (required) Path to the plan Markdown file, or a keyword to search for if the exact path is unknown.

Process (Step 0 + loop):

  1. Step 0 — Resolve the plan file: If the argument is a path to an existing file, use it. Otherwise, glob **/*.md, keyword-match candidates, and keep only those with at least one unchecked task. Halt and ask the user on ambiguity or no match.

Loop body (repeats until plan-progress.sh reports exit 1 — all tasks complete):

  1. Progress: Runs bash ~/.claude/scripts/plan-progress.sh <plan-file> and shows the first two lines of output verbatim, unreformatted. Exit 1 → all tasks complete, stop. Exit 2/3 → halt with error. Exit 0 → note NEXT_TASK_NAME and continue.
  2. Implement next task (inline): Prints Starting task <NEXT_TASK_NAME> at [HH:MM:SS], then runs /implement-next directly in the current context — no subagent is spawned. The same scope rules as /implement-all apply: exactly one task, and the turn only ends once implementation, /iterative-review, passing tests, the checkbox flip, a single commit, and /implement-next Step 7's report are all done.
  3. Recovery check — verify the task landed: Checks that the task is checked off in the plan file and that related files are committed. If not checked, goes back to step 2 and retries (up to 3 attempts, then stops and reports for manual intervention). If checked but uncommitted, commits only the files belonging to this task by explicit path (never git add -A) and reports it as a violation.

Related tools

  • /implement-all — The version-aware wrapper: spawns a subagent per task when the Agent tool is available (Claude Code ≥ 2.1.172), and falls back to this command otherwise.
  • /implement-next — The single-task implementation command this loop runs inline for each task; runs TDD, critical review, tests, check-off, and commit.
  • /iterative-review — Devil's advocate review loop invoked by /implement-next during each task's implementation.
  • scripts-plan — The plan-progress.sh script called at the start of each iteration.
