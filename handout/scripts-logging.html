← Back to index

Summary

Six shell scripts (prompt_log_lib.sh, prompt_log_new_session.sh, prompt_log_save.sh, prompt_log_stop.sh, prompt_log_subagent.sh, prompt_log_usage.sh), a shared jq engine (prompt_log_usage.jq) and a static price table (prompt_log_prices.json) that automatically capture every prompt submitted to Claude Code — together with the assistant's response, the working time, an estimated token/price line, model and effort switches, and one line per finished sub-agent — into per-project Markdown log files, organized by session. The aggregator totals a whole session on demand, sub-agent transcripts included.

When to use

Use /session-log on to enable logging. That only creates the sentinel file ~/.claude/prompt-logs/.enabled — the hooks themselves ship with the plugin (see Hook wiring below), so nothing is written to ~/.claude/settings.json.

  • prompt_log_new_session.sh — called by the SessionStart hook on cold startup (not on resume, /clear, or /compact)
  • prompt_log_save.sh — called by the UserPromptSubmit hook each time you submit a prompt
  • prompt_log_stop.sh — called by the Stop hook when the assistant finishes a response; appends the response, the working time and the estimated token/price line
  • prompt_log_subagent.sh — called by the SubagentStop hook each time a sub-agent finishes; appends one line naming the sub-agent and its transcript
  • prompt_log_lib.sh — an internal shared library; sourced by the scripts above, never invoked directly
  • prompt_log_usage.sh — the standalone aggregator; no hook calls it, you run it yourself to total a session
  • prompt_log_usage.jq — the shared token/price engine, used by both prompt_log_stop.sh and the aggregator so the per-request lines and the totals can never disagree
  • prompt_log_prices.json — the static per-MTok price table the engine reads; a checked-in file, so pricing is deterministic and works offline

Invoke the hook scripts manually only when debugging the logging setup or when writing a script that needs to create or append to a session log file programmatically.

Dependency: jq must be installed and on PATH. If jq is absent, the logging scripts exit silently without error.

Configuration

Enabling and disabling logging

Logging is gated on a sentinel file, ~/.claude/prompt-logs/.enabled. Run /session-log on to create it and /session-log off to remove it; /session-log status reports the current state and, when logging is on, prints the aggregator's totals for the current session. Every hook exits silently when the sentinel is absent, so the hooks stay registered either way and the setting survives plugin updates.

Hook wiring

The hooks are registered automatically from the plugin's hooks/hooks.json — no settings.json edit is needed, and the plugin manifest must not declare a hooks key of its own: on Claude Code 2.1.231 that hard-errors as a duplicate registration and unregisters every hook the plugin provides. All four entries (SessionStart, UserPromptSubmit, Stop, SubagentStop) resolve their script defensively:

s="${CLAUDE_PLUGIN_ROOT}/scripts/prompt_log_new_session.sh"; s="${s//\\//}"; [ -f "$s" ] && exec bash "$s"; exit 0

That one-liner is shaped by how Claude Code hands the plugin root to a hook, plus two Windows bugs closed upstream as not planned or duplicate:

  • Double quotes around the placeholder. Claude Code 2.1.231 no longer substitutes ${CLAUDE_PLUGIN_ROOT} into the command text — it exports it as an environment variable and leaves the expansion to the shell. Single quotes block that expansion, so $s keeps the literal placeholder, the [ -f "$s" ] guard never matches, and the hook exits 0 without doing anything; that is exactly how the logging hooks went silently dead. Double quotes stay safe on Windows because an expanded variable's value is not re-scanned for escapes — under the older textual substitution it was, which is why the pattern used to need single quotes (#22449).
  • Backslash-to-slash normalisation. Git Bash resolves C:/Users/… but not C:\Users\…, so the path is rewritten before use.
  • Shell form, not exec form. Exec form would spawn bash through the Windows PATH, where Git for Windows' default install omits Git\bin (#22700) and the WSL stub C:\Windows\System32\bash.exe takes priority and hangs the whole TUI (#37634). Staying in shell form means bash resolves inside Git Bash's own PATH instead.

The [ -f "$s" ] guard is the honest fallback: where the platform mangles the path beyond repair the hook exits 0 silently, so logging is simply unavailable there rather than printing an error banner on every prompt. Write the placeholder exactly as ${CLAUDE_PLUGIN_ROOT}: that spelling survives both regimes — older Claude Code replaces the literal token before the shell ever sees it, 2.1.231 expands it from the environment — whereas $CLAUDE_PLUGIN_ROOT or ${CLAUDE_PLUGIN_ROOT:-…} only work under the newer one.

Invocation

prompt_log_new_session.sh — Session initialiser

Called automatically by the SessionStart hook. Reads a JSON payload from stdin.

echo '{"session_id":"abc123","cwd":"/path/to/project"}' | bash prompt_log_new_session.sh

Creates a new timestamped session log file under ~/.claude/prompt-logs/<project-slug>/session_YYYY-MM-DD_HH-MM-SS.md and writes a session map entry to ~/.claude/session-maps/<session_id>.

prompt_log_save.sh — Prompt appender

Called automatically by the UserPromptSubmit hook. Reads a JSON payload from stdin.

echo '{"session_id":"abc123","prompt":"your prompt text","cwd":"/path/to/project"}' | bash prompt_log_save.sh

Appends the prompt text with a HH:MM:SS timestamp heading to the session log file. If no session map exists yet, calls create_session_file internally (graceful late-init). It also stamps the request's start time (epoch seconds) into ~/.claude/session-maps/<session_id>.pstart, which the Stop hook reads to compute the working time.

prompt_log_stop.sh — Response and measurement appender

Called automatically by the Stop hook when the assistant finishes a response. Reads a JSON payload from stdin.

echo '{"session_id":"abc123","transcript_path":"/Users/alice/.claude/projects/Users-alice-projects-my-app/abc123.jsonl","last_assistant_message":"Done.","effort":{"level":"high"}}' | bash prompt_log_stop.sh

Appends a ### HH:MM:SS response heading with the assistant's final message verbatim, then the working time: and est. used token: lines, plus a switched: line when the model or effort differs from the previous request. No hook payload carries token usage, so the numbers are read from the transcript and deduped by message.id — one API response yields one assistant entry per content block, each repeating the same usage, so a naive sum would overcount several times over.

Two behaviours are load-bearing. The script exits without writing when the payload carries an agent_id, because that is a sub-agent's Stop, not the session's — sub-agents are covered by SubagentStop instead. And it never writes to stdout and always exits 0: exit code 2 from a Stop hook blocks the session from stopping, so a logging failure must never surface there. An unreadable transcript still logs the response and the working time; only the usage line is skipped.

prompt_log_subagent.sh — Sub-agent line appender

Called automatically by the SubagentStop hook each time a sub-agent finishes. Reads a JSON payload from stdin.

echo '{"session_id":"abc123","transcript_path":"/Users/alice/.claude/projects/Users-alice-projects-my-app/abc123.jsonl","agent_id":"9f3c2a1b","agent_type":"general-purpose"}' | bash prompt_log_subagent.sh

Appends one line: HH:MM:SS sub-agent finished: <agent_type> (agent-<agent_id>), jsonl: <path>. The payload's transcript_path is the parent session's, so the sub-agent transcript is derived from its directory as <dir>/<session_id>/subagents/agent-<agent_id>.jsonl; when that file is not there the line ends with (not found) rather than pointing at nothing. Like the Stop script it stays silent and always exits 0.

prompt_log_lib.sh — Shared library (internal)

Not invoked directly. Provides the create_session_file(session_id, cwd) function plus the pure helpers fmt_hms (seconds → HH:MM:SS), switch_line (renders the switched: line, or nothing when neither model nor effort changed) and resolve_project_key (working directory → the ~/.claude/projects/ slug). Sourced at the top of the scripts above.

source "$(dirname "${BASH_SOURCE[0]}")/prompt_log_lib.sh"

prompt_log_usage.sh — Session aggregator

The one script you run yourself. Takes a session id, a transcript path, or --latest for the newest transcript of the current project.

bash prompt_log_usage.sh --latest
bash prompt_log_usage.sh a1b2c3d4e5f6 --check

Prints one numbered line per request (timestamp, the head of the prompt, and the same est. used token: line the log carries), then one line per sub-agent transcript found under <dir>/<session_id>/subagents/ — searched recursively, so agents spawned inside workflows are counted too — and finally TOTAL (N requests, M sub-agents) with the merged figures. Every transcript is counted exactly once regardless of how deeply the sub-agents nest.

--check is a cross-check, not a price source: when ccusage is on PATH it runs ccusage session -i <session_id> --json and prints that total beside ours, flagging any drift. Drift is the signal that prompt_log_prices.json needs updating; the table stays the single source of truth so a log line and a later total can never disagree. With ccusage absent the flag prints a skip note.

Example 1 — New session initialization

Trigger: A new Claude Code session starts in a project directory (automatic via SessionStart hook).

Effective input (JSON payload sent to stdin by the hook):

{
  "session_id": "a1b2c3d4e5f6",
  "cwd": "/Users/alice/projects/my-app"
}

Result:

# Prompts — 2026-06-05 09:14:32

**Session ID:** a1b2c3d4e5f6
**Resume:** `claude --resume a1b2c3d4e5f6`
**Session file:** `~/.claude/projects/Users-alice-projects-my-app/a1b2c3d4e5f6.jsonl`

---

The file is written to ~/.claude/prompt-logs/projects-my-app/session_2026-06-05_09-14-32.md (slug = last two path segments joined by -). The session map entry at ~/.claude/session-maps/a1b2c3d4e5f6 records the path to this file with permissions 600.

Example 2 — Prompt save

Trigger: You submit a prompt in an active Claude Code session (automatic via UserPromptSubmit hook).

Effective input (JSON payload sent to stdin by the hook):

{
  "session_id": "a1b2c3d4e5f6",
  "prompt": "Implement the next uncompleted task in plans/FEAT-001.md",
  "cwd": "/Users/alice/projects/my-app"
}

Result appended to the session log file:

## 09:15:44

Implement the next uncompleted task in plans/FEAT-001.md

---

Each subsequent prompt appends a new ## HH:MM:SS section to the same file, building a full chronological record of the session's prompts. The response and the measurements land in that same section later, when the assistant stops — see Example 3.

Example 3 — A complete request block

Trigger: one full turn — you submit a prompt, a background sub-agent finishes, the assistant answers, and you had switched model and effort since the previous turn.

Result in the session log file:

## 14:02:11

<prompt>

---

14:03:05 sub-agent finished: general-purpose (agent-9f3c2a1b), jsonl: /Users/…/<sid>/subagents/agent-9f3c2a1b.jsonl

### 14:05:53 response

<last_assistant_message verbatim>

working time: 00:03:42
est. used token: input: 2000, output: 1000, cache_create: 150000, cache_read: 0, total_tokens: 153000, price: $2.32, model: claude-fable-5, effort: max
switched: model claude-sonnet-4-6 → claude-fable-5, effort high → max

---

Everything is written to be grep-able: ^### .* response$, ^est\. used token:, ^switched: and sub-agent finished: each pick out exactly one kind of line. total_tokens is input + output + cache_create + cache_read, and cache_create is the 5-minute and 1-hour cache writes added together — priced separately, since a 1-hour write costs 2× the input rate against 1.25× for a 5-minute one.

The price is an estimate — hence est. — computed from the checked-in table; a model missing from it contributes $0 and gets a ? suffix. The switched: line appears only when the model or the effort actually changed, and it is worth reading: switching models resets the prompt cache, so the request right after a switch pays for a full cache write.
