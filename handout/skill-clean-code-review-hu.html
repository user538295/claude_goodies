Összefoglaló

Kész a kód — mielőtt kiszállítod, kérj mély átvizsgálást. 85 ellenőrzést futtat 7 csoportban (clarity, smells, SOLID, arch, tests, safety, DDD), csoportonként egy párhuzamos ágenssel, és súlyosság szerint szintetizálja az eredményeket. Működik helyi változásokra, staged fájlokra, git-tartományokra vagy explicit fájlútvonalakra — git nélkül is, ha útvonalakat adsz meg.

Mikor használd

Megírtad a kódot, és strukturált átvizsgálást szeretnél PR nyitása előtt — nem hangulatellenőrzést, hanem szisztematikus átmenetet 85 nevesített kritériumon. Akkor nyúlj a /clean-code-review-hoz, ha csoportosított, súlyossággal jelölt és összegzett eredménylistát szeretnél.

Triggerkifejezések (a SKILL.md-ből):

  • "review my code"
  • "check the code quality"
  • "run a clean code review"
  • "review these changes"
  • /clean-code-review

Meghívás

/clean-code-review [TARGET ...] [GROUP ...]

Célok (alapértelmezett: összes helyi változás):

  • nincs vagy local — staged + unstaged + untracked változások
  • staged / unstaged / untracked — csak azok; kombinálható
  • Git-ref vagy tartomány — main..HEAD, HEAD~3, abc123..def456
  • Egy vagy több fájlútvonal — az egész fájlt vizsgálja; ez az egyetlen mód, ami git-repón kívül is működik

Csoportok (kis- és nagybetű-érzéketlen, kihagyva mind a 7 fut):

  • clarity (17 ellenőrzés) · smells (19) · solid (15) · arch (10) · tests (12) · safety (7) · ddd (5)

Súlyossági szintek: Critical (helyesség/biztonság) · Major (design-hiba, valószínű bug) · Moderate (szuboptimális) · Minor (stílus, elnevezés)

1. példa — Helyi változások teljes átvizsgálása

Bemenet:

/clean-code-review

Kimenet / Eredmény:

Target: local changes (staged + unstaged + untracked)
Running 7 groups in parallel…

── Results ───────────────────────────────────────────
Group     Checks  Findings
────────  ──────  ────────────────────────────────────
clarity      17   1 Minor — method name does not express intent
smells       19   1 Moderate — duplicated validation logic in 3 places
solid        15   2 Major findings:
                    • UserService handles auth, email, and billing (god class)
                    • PaymentProcessor depends on concrete DB class, not interface
arch         10   0
tests        12   1 Moderate — happy path only; no edge cases for null input
safety        7   0
ddd           5   0

── Synthesis ─────────────────────────────────────────
Critical  0
Major     2  ← fix before merge
Moderate  2
Minor     1

Recommended next step: fix the two Major findings in `solid`.
Run /clean-code-review solid to recheck after.

2. példa — Egyetlen csoport egy git-tartományra

Bemenet:

/clean-code-review main..HEAD safety

Kimenet / Eredmény:

Target: main..HEAD
Group: safety (7 checks)

── Results ───────────────────────────────────────────
✗ Major   — Hardcoded API key in src/config/api.py (line 14).
            Rotate the key; move to environment variable.
✗ Minor   — No input length validation on POST /api/users/register.
            A 10 MB payload hits the DB before any guard runs.

── Synthesis ─────────────────────────────────────────
Critical  0
Major     1  ← fix before merge
Minor     1

Kapcsolódó eszközök

  • /da-review — Egymenetes adversarial review; könnyebb és gyorsabb, nincs csoportstruktúra. Gyors józanság-ellenőrzéshez jó; a /clean-code-review mélyebbre megy.
  • /iterative-review — Javításokat is alkalmazó review-hurok. Akkor nyúlj hozzá, ha azt szeretnéd, hogy a problémák meg is oldódjanak, ne csak listázva legyenek.
  • /aaa — Világszínvonalú példákhoz méri az eredményt, és fejlesztési utakat ad vissza. Használd a /clean-code-review után, ha a "nincs találat" még nem elég.
