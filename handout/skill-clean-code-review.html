Summary

Code done — get the deep read before it ships. Runs 109 checks across 7 groups (clarity, smells, SOLID, arch, tests, safety, DDD), spawns one agent per group in parallel, and synthesizes findings by severity. Works on local changes, staged files, git ranges, or explicit paths — no git required for file-path mode.

Scripted detections run first via collect.sh and are handed to the group agents as precomputed hits — agents confirm or dismiss each one rather than re-running detection. Vendor and generated files are excluded upfront. Per-check findings can be capped on very large diffs; the report notes it when that happens.

When to use

You've written the code and want a structured review before opening a PR — not a vibe check, a systematic pass across 109 named criteria. Use /clean-code-review when you want findings grouped, labeled by severity, and synthesized into a clear action list.

The skill declares no trigger phrases — invoke it directly with /clean-code-review.

Invocation

/clean-code-review [TARGET ...] [GROUP ...]

Targets (default: all local changes):

  • none or local — staged + unstaged + untracked changes
  • staged / unstaged / untracked — only those areas; combinable
  • A git ref or range — main..HEAD, HEAD~3, abc123..def456. A single ref diffs against the worktree. Not combinable with the keywords above.
  • One or more file paths — reviews the whole files; the only mode that works outside a git repo

Groups (case-insensitive, omit to run all 7):

  • clarity (17 checks) · smells (23) · solid (15) · arch (11) · tests (13) · safety (21) · ddd (9)

A token that matches a group name is always treated as a group, never as a file or ref — e.g. /clean-code-review tests selects the tests group, not a directory named tests.

Language gate: if no supported language file is detected in the target, the review aborts before spawning any agent: "No supported language files detected. Supported: TypeScript, JavaScript, C#, Python, Swift, Kotlin, Java. Unanalysed: {contents of unanalysed.txt}."

Severity levels: Critical (blocks correctness, security, or safety) · Major (significant design flaw, missing requirement, or likely bug) · Moderate (suboptimal but workable) · Minor (style, naming, or nitpick)

Related tools

  • /da-review — Single-pass adversarial review; lighter and faster, no group structure. Good for a quick sanity check; /clean-code-review goes deeper.
  • /iterative-review — Review loop that also applies fixes. When /clean-code-review is installed and the target is code, its cycle 1 also runs one /clean-code-review pass as an extra catalog check, labeling its findings C1-CC-N alongside the devil's advocate findings. Reach for it when you want problems resolved, not just listed.
  • /aaa — Benchmarks against world-class examples and returns upgrade paths. Use after /clean-code-review when "no findings" isn't enough.
