Summary

Code done — get the deep read before it ships. Runs 85 checks across 7 groups (clarity, smells, SOLID, architecture, tests, safety, DDD), spawns one agent per group in parallel, and synthesizes findings by severity. Works on local changes, staged files, git ranges, or explicit paths — no git required for file-path mode.

When to use

You've written the code and want a structured review before opening a PR — not a vibe check, a systematic pass across 85 named criteria. Use /clean-code-review when you want findings grouped, labeled by severity, and synthesized into a clear action list.

Trigger phrases (from SKILL.md):

  • "review my code"
  • "check the code quality"
  • "run a clean code review"
  • "review these changes"
  • /clean-code-review

Invocation

/clean-code-review [TARGET ...] [GROUP ...]

Targets (default: all local changes):

  • none or local — staged + unstaged + untracked changes
  • staged / unstaged / untracked — only those areas; combinable
  • A git ref or range — main..HEAD, HEAD~3, abc123..def456
  • One or more file paths — reviews the whole files; the only mode that works outside a git repo

Groups (case-insensitive, omit to run all 7):

  • clarity (17 checks) · smells (19) · solid (15) · arch (10) · tests (12) · safety (7) · ddd (5)

Severity levels: Critical (correctness/security) · Major (design flaw, likely bug) · Moderate (suboptimal) · Minor (style, naming)

Example 1 — Full review of local changes

Input:

/clean-code-review

Output / Result:

Target: local changes (staged + unstaged + untracked)
Running 7 groups in parallel…

── Synthesis ─────────────────────────────────────────

Recommended next step: fix the two Major findings in `solid`.
Run /clean-code-review solid to recheck after.

Example 2 — Single group on a git range

Input:

/clean-code-review main..HEAD safety

Output / Result:

Target: main..HEAD
Group: safety (7 checks)

── Results ───────────────────────────────────────────
✗ Major   — Hardcoded API key in src/config/api.py (line 14).
            Rotate the key; move to environment variable.
✗ Minor   — No input length validation on POST /api/users/register.
            A 10 MB payload hits the DB before any guard runs.

── Synthesis ─────────────────────────────────────────
Critical  0
Major     1  ← fix before merge
Minor     1

Related tools

  • /da-review — Single-pass adversarial review; lighter and faster, no group structure. Good for a quick sanity check; /clean-code-review goes deeper.
  • /iterative-review — Review loop that also applies fixes. Reach for it when you want problems resolved, not just listed.
  • /aaa — Benchmarks against world-class examples and returns upgrade paths. Use after /clean-code-review when "no findings" isn't enough.
