Összefoglaló

Hat shell szkript (prompt_log_lib.sh, prompt_log_new_session.sh, prompt_log_save.sh, prompt_log_stop.sh, prompt_log_subagent.sh, prompt_log_usage.sh), egy közös jq motor (prompt_log_usage.jq) és egy statikus ártáblázat (prompt_log_prices.json), amelyek automatikusan rögzítenek minden, a Claude Code-nak elküldött promptot — az asszisztens válaszával, a kérésre fordított idővel, a becsült token/ár sorral, a modell- és effort-váltásokkal, valamint minden befejeződött alügynökről egy sorral együtt — projektenkénti Markdown naplófájlokba, sessionönként rendezve. Az aggregátor kérésre összesíti a teljes sessiont, az alügynökök transcriptjeivel együtt.

Mikor használd

A naplózás engedélyezéséhez futtasd a /session-log on parancsot. Ez csak létrehozza a ~/.claude/prompt-logs/.enabled sentinel fájlt — magukat a hookokat a plugin szállítja (lásd lentebb a Hook bekötés részt), így a ~/.claude/settings.json fájlba semmi nem íródik.

  • prompt_log_new_session.sh — a SessionStart hook hívja hideg indításkor (nem érvényes resume, /clear, vagy /compact esetén)
  • prompt_log_save.sh — a UserPromptSubmit hook hívja minden alkalommal, amikor promptot küldesz
  • prompt_log_stop.sh — a Stop hook hívja, amikor az asszisztens befejezi a választ; hozzáfűzi a választ, a ráfordított időt és a becsült token/ár sort
  • prompt_log_subagent.sh — a SubagentStop hook hívja minden alkalommal, amikor egy alügynök befejeződik; egy sort fűz hozzá az alügynök nevével és a transcriptjének útvonalával
  • prompt_log_lib.sh — belső, megosztott függvénykönyvtár; a fenti szkriptek source-olják, közvetlenül soha nem hívod
  • prompt_log_usage.sh — az önálló aggregátor; nem hook hívja, hanem te futtatod, ha összesíteni akarsz egy sessiont
  • prompt_log_usage.jq — a közös token/ár motor, amelyet a prompt_log_stop.sh és az aggregátor egyaránt használ, így a kérésenkénti sorok és az összesítés soha nem mondhat ellent egymásnak
  • prompt_log_prices.json — a statikus, MTok-onkénti ártáblázat, amelyet a motor olvas; verziókövetett fájl, így az árazás determinisztikus és offline is működik

A hook szkripteket kézzel csak akkor indítsd, ha a logging beállítást debugolod, vagy ha olyan szkriptet írsz, amelynek programozottan kell létrehoznia vagy bővítenie egy session naplófájlt.

Függőség: A jq-nak telepítve kell lennie és elérhetőnek kell lennie a PATH-ban. Ha a jq hiányzik, a logging szkriptek csendesen kilépnek, hiba nélkül.

Konfiguráció

Naplózás be- és kikapcsolása

A naplózást egy sentinel fájl vezérli: ~/.claude/prompt-logs/.enabled. A /session-log on létrehozza, a /session-log off eltávolítja, a /session-log status pedig kiírja az aktuális állapotot; az aggregátor összesítését az aktuális sessionre a /session-log usage adja. Ha a sentinel nincs meg, minden hook csendben kilép, így a hookok bekötve maradhatnak, és a beállítás túléli a plugin-frissítéseket.

Hook bekötés

A hookok automatikusan bekötődnek a plugin hooks/hooks.json fájljából — nem kell settings.json-t szerkeszteni, és a plugin manifest sem deklarálhat saját hooks kulcsot: a Claude Code 2.1.231-en ez duplikált bekötésként hibára fut, és a plugin összes hookját kiregisztrálja. Mind a négy bejegyzés (SessionStart, UserPromptSubmit, Stop, SubagentStop) védelmezően oldja fel a szkript útvonalát:

s="${CLAUDE_PLUGIN_ROOT}/skills/session-log/scripts/prompt_log_new_session.sh"; s="${s//\\//}"; [ -f "$s" ] && exec bash "$s"; exit 0

Az egysorost az alakítja, ahogyan a Claude Code átadja a plugin gyökerét a hooknak, plusz két windowsos hiba, amelyeket not planned vagy duplicate címkével zártak upstream:

  • Idézőjelek a placeholder körül. A Claude Code 2.1.231 már nem helyettesíti be textuálisan a ${CLAUDE_PLUGIN_ROOT} értéket a command szövegébe — környezeti változóként exportálja, a behelyettesítést a shellre bízza. Az aposztrófok blokkolnák ezt a behelyettesítést, így az $s a nyers placeholder maradna, a [ -f "$s" ] ellenőrzés soha nem találna semmit, és a hook 0-val kilépne anélkül, hogy bármit csinálna; pontosan így haltak el csendben a logging hookok. Az idézőjelek Windowson is biztonságosak, mert a behelyettesített változó értékét a shell már nem vizsgálja újra escape-ekre — a régi, textuális behelyettesítésnél viszont igen, ezért volt korábban szükség aposztrófokra (#22449).
  • Visszaperjel–perjel normalizálás. A Git Bash a C:/Users/… formát feloldja, a C:\Users\…-t nem, ezért az útvonalat átírjuk használat előtt.
  • Shell forma, nem exec forma. Az exec forma a bash-t a windowsos PATH-ról indítaná, ahol a Git for Windows alapértelmezett telepítése kihagyja a Git\bin-t (#22700), a C:\Windows\System32\bash.exe WSL-stub pedig elsőbbséget kap és az egész TUI-t megfagyasztja (#37634). Shell formában maradva a bash a Git Bash saját PATH-ján oldódik fel.

A [ -f "$s" ] ellenőrzés a becsületes tartalék: ahol a platform javíthatatlanul elrontja az útvonalat, a hook csendben 0-val kilép, így a naplózás ott egyszerűen nem elérhető, nem pedig minden promptnál hibasávot ír ki. A placeholdert pontosan ${CLAUDE_PLUGIN_ROOT} alakban írd: ez mindkét működésmódot túléli — a régebbi Claude Code ezt a konkrét tokent cseréli le, mielőtt a shell egyáltalán látná, a 2.1.231 pedig a környezetből oldja fel —, míg a $CLAUDE_PLUGIN_ROOT vagy a ${CLAUDE_PLUGIN_ROOT:-…} változat csak az újabbal működik.

Meghívás

prompt_log_new_session.sh — Session inicializáló

A SessionStart hook automatikusan hívja. JSON payloadot olvas a stdin-ről.

echo '{"session_id":"abc123","cwd":"/path/to/project"}' | bash prompt_log_new_session.sh

Új, időbélyeggel ellátott session naplófájlt hoz létre a ~/.claude/prompt-logs/<project-slug>/session_YYYY-MM-DD_HH-MM-SS.md alatt, és session map bejegyzést ír a ~/.claude/session-maps/<session_id> útvonalra.

prompt_log_save.sh — Prompt hozzáfűző

A UserPromptSubmit hook automatikusan hívja. JSON payloadot olvas a stdin-ről.

echo '{"session_id":"abc123","prompt":"your prompt text","cwd":"/path/to/project"}' | bash prompt_log_save.sh

A prompt szövegét egy HH:MM:SS időbélyeges címsorral fűzi hozzá a session naplófájlhoz. Ha még nincs session map, belsőleg meghívja a create_session_file függvényt (elegáns késői inicializálás). Emellett a kérés kezdetének idejét (epoch másodpercben) beírja a ~/.claude/session-maps/<session_id>.pstart fájlba, amelyből a Stop hook kiszámolja a ráfordított időt.

prompt_log_stop.sh — Válasz- és mérésrögzítő

A Stop hook automatikusan hívja, amikor az asszisztens befejezi a választ. JSON payloadot olvas a stdin-ről.

echo '{"session_id":"abc123","transcript_path":"/Users/alice/.claude/projects/Users-alice-projects-my-app/abc123.jsonl","last_assistant_message":"Kész.","effort":{"level":"high"}}' | bash prompt_log_stop.sh

Egy ### HH:MM:SS response címsort fűz hozzá az asszisztens utolsó üzenetével szó szerint, majd a working time: és az est. used token: sorokat, továbbá egy switched: sort, ha a modell vagy az effort eltér az előző kéréstől. Egyik hook payload sem tartalmazza a token-felhasználást, ezért a számok a transcriptből jönnek, message.id szerint deduplikálva — egy API-válasz tartalmi blokkonként külön assistant bejegyzést hoz létre, és mindegyik ugyanazt a usage értéket ismétli, így a naiv összeadás többszörösen felülszámolna.

Két viselkedés kritikus. A szkript írás nélkül kilép, ha a payloadban szerepel agent_id: az egy alügynök Stopja, nem a sessioné — az alügynököket a SubagentStop fedi le. És soha nem ír a stdout-ra, mindig 0-val lép ki: egy Stop hook 2-es kilépési kódja megakadályozná a session leállását, ezért egy naplózási hiba ott soha nem bukkanhat fel. Olvashatatlan transcript esetén a válasz és a ráfordított idő így is naplózódik, csak a usage sor marad ki.

prompt_log_subagent.sh — Alügynök-sor hozzáfűző

A SubagentStop hook automatikusan hívja minden alkalommal, amikor egy alügynök befejeződik. JSON payloadot olvas a stdin-ről.

echo '{"session_id":"abc123","transcript_path":"/Users/alice/.claude/projects/Users-alice-projects-my-app/abc123.jsonl","agent_id":"9f3c2a1b","agent_type":"general-purpose"}' | bash prompt_log_subagent.sh

Egyetlen sort fűz hozzá: HH:MM:SS sub-agent finished: <agent_type> (agent-<agent_id>), jsonl: <útvonal>. A payload transcript_path mezője a szülő sessionre mutat, ezért az alügynök transcriptje ennek könyvtárából áll elő: <könyvtár>/<session_id>/subagents/agent-<agent_id>.jsonl; ha ez a fájl nincs meg, a sor (not found) jelzéssel zárul, nem pedig a semmibe mutat. A Stop szkripthez hasonlóan néma marad, és mindig 0-val lép ki.

prompt_log_lib.sh — Megosztott függvénykönyvtár (belső)

Közvetlenül nem hívod. A create_session_file(session_id, cwd) függvényt biztosítja, valamint a fmt_hms (másodperc → HH:MM:SS), a switch_line (a switched: sort állítja elő, vagy semmit, ha sem a modell, sem az effort nem változott) és a resolve_project_key (munkakönyvtár → a ~/.claude/projects/ alatti slug) tiszta segédfüggvényeket. A fenti szkriptek tetején source-olva van.

source "$(dirname "${BASH_SOURCE[0]}")/prompt_log_lib.sh"

prompt_log_usage.sh — Session-aggregátor

Az egyetlen szkript, amelyet magad futtatsz. Elfogad session id-t, transcript útvonalat, vagy a --latest kapcsolót az aktuális projekt legfrissebb transcriptjéhez.

bash prompt_log_usage.sh --latest
bash prompt_log_usage.sh a1b2c3d4e5f6 --check

Kérésenként egy számozott sort ír ki (időbélyeg, a prompt eleje, és ugyanaz az est. used token: sor, amely a naplóban is szerepel), majd egy-egy sort minden alügynök-transcriptre, amelyet a <könyvtár>/<session_id>/subagents/ alatt talál — rekurzívan keresve, így a workflow-kon belül indított ügynökök is beleszámítanak —, végül a TOTAL (N requests, M sub-agents) sort az összesített értékekkel. Minden transcript pontosan egyszer számít bele, bármilyen mélyen ágyazódnak is egymásba az alügynökök.

A --check keresztellenőrzés, nem árforrás: ha a ccusage elérhető a PATH-on, lefuttatja a ccusage session -i <session_id> --json parancsot, és a mi összegünk mellé kiírja az övét, jelezve az eltérést. Az eltérés arra utal, hogy a prompt_log_prices.json frissítésre szorul; az ártáblázat marad az egyetlen igazságforrás, így egy naplósor és egy későbbi összesítés soha nem mondhat ellent egymásnak. Ha a ccusage nincs telepítve, a kapcsoló csak egy kihagyást jelző megjegyzést ír ki.

1. példa — Új session inicializálása

Trigger: egy új Claude Code session indul egy projektkönyvtárban (automatikus a SessionStart hookon keresztül).

Tényleges bemenet (a hook által stdin-re küldött JSON payload):

{
  "session_id": "a1b2c3d4e5f6",
  "cwd": "/Users/alice/projects/my-app"
}

Eredmény:

# Prompts — 2026-06-05 09:14:32

**Session ID:** a1b2c3d4e5f6
**Resume:** `claude --resume a1b2c3d4e5f6`
**Session file:** `~/.claude/projects/Users-alice-projects-my-app/a1b2c3d4e5f6.jsonl`

---

A fájl a ~/.claude/prompt-logs/projects-my-app/session_2026-06-05_09-14-32.md útvonalra íródik (a slug = az útvonal utolsó két szegmense - jellel összefűzve). A ~/.claude/session-maps/a1b2c3d4e5f6 alatti session map bejegyzés rögzíti ennek a fájlnak az útvonalát, 600 jogosultsággal.

2. példa — Prompt mentése

Trigger: egy aktív Claude Code sessionben promptot küldesz (automatikus az UserPromptSubmit hookon keresztül).

Tényleges bemenet (a hook által stdin-re küldött JSON payload):

{
  "session_id": "a1b2c3d4e5f6",
  "prompt": "Implement the next uncompleted task in plans/FEAT-001.md",
  "cwd": "/Users/alice/projects/my-app"
}

A session naplófájlhoz hozzáfűzött eredmény:

## 09:15:44

Implement the next uncompleted task in plans/FEAT-001.md

---

Minden további prompt egy új ## HH:MM:SS szakaszt fűz ugyanahhoz a fájlhoz, így a session promptjairól teljes, időrendi feljegyzés épül. A válasz és a mérések ugyanebbe a szakaszba kerülnek később, amikor az asszisztens befejezi a választ — lásd a 3. példát.

3. példa — Egy teljes kérés-blokk

Trigger: egy teljes kör — promptot küldesz, közben befejeződik egy háttérben futó alügynök, az asszisztens válaszol, és az előző kör óta modellt és effortot is váltottál.

Eredmény a session naplófájlban:

## 14:02:11

<prompt>

---

14:03:05 sub-agent finished: general-purpose (agent-9f3c2a1b), jsonl: /Users/…/<sid>/subagents/agent-9f3c2a1b.jsonl

### 14:05:53 response

<last_assistant_message verbatim>

working time: 00:03:42
est. used token: input: 2000, output: 1000, cache_create: 150000, cache_read: 0, total_tokens: 153000, price: $2.32, model: claude-fable-5, effort: max
switched: model claude-sonnet-4-6 → claude-fable-5, effort high → max

---

Minden sor grepelhetőre van tervezve: a ^### .* response$, az ^est\. used token:, a ^switched: és a sub-agent finished: mind pontosan egyféle sort emel ki. A total_tokens az input + output + cache_create + cache_read összege, a cache_create pedig az 5 perces és az 1 órás cache-írások együtt — külön áron számolva, mert az 1 órás írás az input-ár 2×-ét viszi, az 5 perces pedig 1,25×-ét.

Az ár becslés — innen az est. —, a verziókövetett táblázatból számolva; a táblázatból hiányzó modell $0-val számít, és ? jelet kap a sor végén. A switched: sor csak akkor jelenik meg, ha a modell vagy az effort tényleg változott, és érdemes figyelni rá: a modellváltás nullázza a prompt cache-t, így a váltás utáni első kérés egy teljes cache-írást fizet meg.
