/status_report

← Back to index

Summary

Kicked off a long task and don't know when it'll finish. Reports status on demand or on a recurring schedule — reads output files, commands, or URLs, extracts progress and ETA, and stops itself when the task completes. Cancel anytime with /status_report off.

When to use

You started a background task — a test suite, build, deploy, migration, data pipeline — and want periodic updates without babysitting it. Works with any output source: a file written by the process, a shell command like kubectl get pods, or a URL.

  • "/status_report" — one check, right now
  • "/status_report 10 mins" — check every 10 minutes until done
  • "/status_report 2h" — check every 2 hours
  • "/status_report off" — stop scheduled checks

Invocation

One-shot — report immediately, no scheduling:

/status_report

Recurring — report every interval until the task completes:

/status_report 10 mins
/status_report 2h
/status_report 30    ← bare integer = minutes

Cancel scheduled checks:

/status_report off
/status_report cancel
/status_report stop

The skill identifies the running task from conversation context — background task ID, output file path, or description. If multiple tasks are found, it uses the most recently launched. If none found, it asks before proceeding.

Tradeoff: recurring checks are tied to the current session. If the session ends, checks stop. Max 24 checks per run (~4 h at 10-minute intervals).

Example 1 — One-shot check

Input:

/status_report

Output / Result:

14:32 - [test suite] Status update #1 - in progress 43% (187/430)

- Running: src/billing, src/users, src/api
- 2 failures in src/notifications (non-blocking)
- No failures in completed packages

Example 2 — Recurring with completion

Input:

/status_report 5 mins

Output / Result:

14:47 - [database migration] Status update #1 - in progress 18% (3/17)

- Applying: 003_add_invoice_index
- Completed: 001_users, 002_billing
- No errors so far

ETA: 15:11
Next check scheduled for 14:52

[5 minutes later — automatic wakeup]

14:52 - [database migration] Status update #2 - complete 100% (17/17)

- All 17 migrations applied successfully
- Migration time: 4m 38s

Run complete — no further checks scheduled.

Related tools

  • /wrap-up — End-of-session audit for when the task is code work; /status_report is for monitoring any running process.
  • /bugfix — Runs a multi-step pipeline that can take time; use /status_report to monitor it from another session if needed.
